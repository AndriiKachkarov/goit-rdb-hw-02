# Проєкт: Нормалізація бази даних замовлень

Цей проєкт демонструє процес приведення необроблених даних до третьої нормальної форми (3NF) та розробку відповідної ER-діаграми в MySQL Workbench.

## Початкові дані

Об'єктом нормалізації є таблиця замовлень, яка містила:

- неатомарні значення (декілька товарів в одному замовленні);
- надмірність даних (повторення адрес та імен клієнтів).

## Етапи нормалізації

### 1. Перша нормальна форма (1NF)

Файл: `1nf.png`

На цьому етапі було забезпечено атомарність даних:

- кожне поле містить лише одне значення;
- рядки, що містили переліки товарів (наприклад, "Лептоп, Мишка"), розділені на окремі записи;
- визначено складений первинний ключ: `(order_id, product_name)`.

### 2. Друга нормальна форма (2NF)

Файл: `2nf.png`

Мета цього кроку - усунення часткових залежностей:

- таблицю розділено на дві: `orders` (загальна інформація про замовлення) та `order_items` (склад замовлення);
- дані, що залежать лише від `order_id` (дата, клієнт, адреса), винесені в окрему таблицю;
- у таблиці `order_items` залишилися лише ті дані, що залежать від обох частин ключа (кількість конкретного товару).

### 3. Третя нормальна форма (3NF)

Файл: `3nf.png`

На фінальному етапі усунуто транзитивні залежності:

*Клієнти*: Винесені в окрему таблицю `clients`. Адреса та ім'я тепер не дублюються в таблиці замовлень.

*Товари*: Назви товарів винесені в довідник `products`. В таблиці `order_items` зберігаються лише посилання на ID товару. Це дозволяє централізовано керувати каталогом товарів.

## ER-діаграма

Файл: `schema.png`

Фінальна логічна схема бази даних, створена в MySQL Workbench, відображає:

- таблиці: `clients`, `orders`, `order_items`;
- зв'язки:
	- `clients -> orders` (1:N, Non-identifying)
	- `orders -> order_items` (1:N, Identifying)
